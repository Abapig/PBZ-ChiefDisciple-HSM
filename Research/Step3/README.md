# 第三步：全量分层状态机设计图

首选打开 **Boss全量分层状态机.html**。这是一个离线交互画布，所有节点、连线、数据均内嵌，不依赖网络或额外安装软件。

- 滚轮缩放，拖动空白区域平移。
- 左侧分区按钮只移动同一张画布，不切换到另一个页面，也不隐藏其他层级。
- 单击状态，右侧展示完整进入/退出条件、优先级、层级路径、参数和资源占位。
- 双击状态，定位本状态及同区相邻状态，便于看清前后路径。
- 搜索支持状态名、招式编号和条件文本。
- “全图”查看整体；“截图模式”隐藏界面面板，Esc退出。
- “导出全图SVG”始终导出全量节点和连线，不受当前缩放、高亮或线条过滤影响。

## 层级与并行关系

1. **L0 战斗生命周期**：开战、暂停、失败、胜利、Abort、终局封存。
2. **L1 阶段**：M1剑阵 → M2丝线 → M3双人 → 红衣先死时M4；大师兄先死则殉情；同批双亡单独结算。
3. **L2 角色父状态**：大师兄各形态、红衣未入场/活动/死亡、弟子池/活动/死亡/再召唤。
4. **L3 行为与资源**：对峙、转向、追击、侧移、后撤、格挡、闪避、受击、破防、坠地、重悬、脱阵与支援。
5. **L4 动作内部**：逐招前摇、普通拍、连接动作、观察、停招、追加段、彩色末段、收势。

实时压力、跨场学习、事件仲裁、攻击预约是**并行服务区域**，不和角色“当前正在做的动作”竞争一个互斥状态。每名角色各自持有公共行为模板的一份运行实例；图只画一次模板，不代表八个角色共享同一个CurrentState。

白灰实线是状态转换；青色虚线是数据依赖；金色虚线是事件路由；淡红虚线是活动动作继承的全局抢占。父状态收到事件不等于每帧重新执行其Enter。连线类型已写进JSON/CSV，后续落蓝图不得把全部线都机械翻译成互斥状态跳转。

G1死亡/阶段高于G2强制中断，G2高于G3超时恢复；都高于普通连段推进。特殊终局与全阵恢复节点只有适用的更高优先出口。身份字段BattleID/Epoch/ActionID/BeatID贯穿所有事件，旧通知不会重新启动招式。

## 本次必须保留的转换

- M1-02/03固定蓝，M1-04与开场06共用；M1-07大师兄先剑气、最后弟子蓝斩；M1-09满6弟子无光三拍。
- M1两种归阵、2–6弟子阵型与借力次数；任一参阵者真被打断则全阵取消；脱阵非参阵者不触发。
- 单脱阵槽、持续进攻触发支援、普通近战一人/一组、独立剑气例外但仍接受时间预约。
- M1召唤优先于吸血，严格1/3与75%阈值，目标最高绝对HP，资源提交前复查，费用与收益守恒预算。
- M2 A/B/C/D普通第二拍的停招/观察；C/E有限前缀池；蓝突刺只能在末尾；独立蓝刺F。
- M2-03无光；M2-05起手按距离锁定近红/远无光；近红不追加；远无光在已结算结果之后判断蓝刺，重新检查1100cm范围。
- M3继承M2、联合蓝/错拍红、副通道、红衣牺牲生命治疗；M4六刀最后为蓝光斩击。
- 杀气未空可合法格挡；只破防回气；没有闪避无敌帧；坠地与悬吊破防为独立维度。
- 可选被追击/处决只在明确支持、已配置正逻辑时长且收到有效事件时进入；默认关闭。
- 压力本场更新；历史经验本场冻结；每招权重、探索与封顶、连发限制均通过中央选择区域作用于状态守卫。

## 资源命名与空绑定

`MasterActor / DiscipleActors[6] / RedActor` 全部为null。

每个需要动作表现的状态预留 `AN_<实际执行者>_<StateID>`；有效攻击拍另有 `HIT_ / FX_ / SFX_`。多人动作按实际角色拆占位，例如M1-07最后蓝斩绑定LastFormationDisciple，不绑给大师兄；M3联合蓝分别预留Master与Red动画。

这些是**资源接口名称**，没有伪造已存在的.uasset文件。所有binding均为null。没有动画时，正常流程通过已配置逻辑时间推进，不死等Montage结束；没有碰撞资源时不伪造命中结果。可用显式测试事件审阅逻辑，但必须标注是测试输入。

攻击伤害、几何碰撞形状、移动速度、转向率、阵型坐标等保留接口。追击/处决时长未填时功能关闭。归阵总时间、破防起始硬直等必需逻辑计时提供默认，避免空动画导致悬停。
